# 小店实验室

直接复制 ‘ https://umiii777.github.io/lonely-shop/ ’   到网页栏即可打开

单页 H5。用浏览器直接打开 `index.html` 即可，不需要安装依赖，也不需要服务器。

营业约 90 秒。顶部可以暂停、继续、1×、2×，也可以提前打烊。

## 怎么玩

1. 点员工，再点岗位。两个已排班的岗位对点会互换。擅长岗位效率 1.3×，其他岗位 1.0×。
2. 勾选今天的菜，最多两种。
3. 开始营业。订单必须先经过后厨，再收银，再传菜。任一岗排队，后面都会变慢。
4. 结束后看诊断。可以改配置再开，或沿用方案再开一天。顾客到达和点单会重新随机。

可调参数在 `js/config.js`。菜品、耐心、到店间隔、员工加成按需求固定。收银基础耗时 3.8 秒、传菜基础耗时 3.5 秒是平衡参数。

## 测试记录

每组 10 个种子（1 到 10），下表是平均值。瓶颈一列是 10 局里被判定成该瓶颈的次数。队列等待只算排队，不含正在处理的时间。

| 方案 | 完成 | 流失 | 未完成 | 平均等待 | 净利润 | 瓶颈 |
|---|---:|---:|---:|---:|---:|---|
| 均衡排班，只卖面条 | 26.3 | 0.0 | 3.4 | 8.9 秒 | 169.1 | 均衡 10/10 |
| 均衡排班，炒饭 + 面条 | 26.1 | 0.0 | 3.6 | 9.5 秒 | 183.1 | 均衡 10/10 |
| 阿明后厨、大壮收银、小雨传菜，只卖面条 | 18.9 | 2.8 | 8.0 | 16.3 秒 | 117.3 | 收银 10/10 |
| 均衡排班，炒饭 + 招牌大菜 | 17.0 | 4.8 | 7.9 | 16.1 秒 | 136.6 | 后厨 10/10 |
| 大壮后厨、小雨收银、阿明传菜，只卖面条 | 22.9 | 0.0 | 6.8 | 14.0 秒 | 145.3 | 传菜 10/10 |

对照结论：

- 三个岗位都放在擅长位置、只卖快菜时，几乎没有人流失，净利润更高。
- 后厨很快但收银没有加成时，瓶颈稳定落在收银，完成数和净利润都下降。
- 招牌大菜利润更高，但后厨 10/10 成为瓶颈，平均净利润低于只卖面条或炒饭 + 面条。单局波动大：同样的招牌菜单，10 个种子里净利润大约从 65 到 177，差异来自点单构成和到达间隔，不是写死的结果。
- 只把传菜换成没有加成的员工时，瓶颈会改到传菜。

复现：

```bash
node js/balance.js
```

没有 Node 时，在 macOS 上可以用：

```bash
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc js/config.js js/sim.js js/balance.js
```

## 已知问题

- 收银和传菜的基础耗时不在需求表里。把它们改得太短，换岗看不出瓶颈；改得太长，擅长的人也会堵住。
- 招牌大菜单局波动大。瓶颈方向稳定，赚多少不稳定。
- 报告里的平均等待从进店算到离开，包含制作和结算。岗位条只统计排队。
- 时间到或提前打烊时，正在做和还在排队的订单算未完成，不产生收入。所以顺畅的一轮也会留下大约 3 单。
- 桌面优先。窗口变窄后改成上下排列，没有单独的手机操作。
- 没有音效、精细动画和存档。刷新页面会回到 100 元。
- 现金可以变成负数，测试不会因此结束。

## 这次没有做

需求里明确排除的招聘、库存、七日生存、随机事件、扩建和账号，都没有加。

如果以后继续做，优先考虑两件事：打烊后给正在做的单一个很短的收尾时间，以及让招牌大菜的单局波动不要大到盖过配置差异。这次都没有放进原型。
